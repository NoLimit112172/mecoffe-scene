# 本地启动验证

验证环境：Windows，Windows PowerShell 5.1，Node.js 24.15，Python 3.12，VS Code 内置 JavaScript 调试器。

## 已验证

- 在真实 VS Code 工作区停止旧调试会话后，按 F5 执行启动任务；终端显示本项目服务就绪，随后进入 Chrome 调试。
- 访问 `http://127.0.0.1:5180/` 自动转到 `/mecoffe`，显示第 3 版、100 人、530 条关注的动态演示。
- 27 项 Python 适配器测试、17 项前端测试通过，前端生产构建成功。
- 两个启动进程并发冷启动到独立测试端口时，均成功退出，只有一个服务监听。
- 其他 HTTP 服务占用测试端口时，启动被拒绝，原有服务未被结束。
- 为用户旧终端中出现的 `Path/PATH` 重复字典键异常注入同类异常后，隐藏 Node/WMI 回退分支实际冷启动成功；此项并未重建原 VS Code 的完整环境块，也没有改动系统环境变量。
- 独立测试服务已停止，主沙盘服务继续运行。

启动脚本先验证解释器、依赖和场景数据，再检查服务身份及实际返回的新版演示 JSON；确认就绪后才交给浏览器。后台服务使用日志文件，后续排查可查看任务终端和本机 `logs/`。

`frontend/public/mecoffe/runtime-local.json` 是本机生成的服务身份文件，不含绝对路径或凭据，且不提交。环境配置、依赖、构建目录、日志和本机备份同样排除在源码仓库之外。
