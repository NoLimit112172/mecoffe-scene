# 人物进楼：展示层约定（里程碑 9）

本轮优先中科大 `ustc-history`。根据追加要求，**入口统一推断，不读取 OSM entrance 标注**；NUS 只做通用产物兼容及原页面回归，不交付 NUS 入口截图。未增加依赖、外部数据或服务。人物位置、入口、停留与昼夜变化都是展示设定，OASIS 没有位置数据。

## 入口文件

原命令 `python -m adapter.scene_builder scenario --manifest scenarios/ustc-history.json` 额外生成：

- `entrances.json`：`mecoffe.entrances.v1`，米制坐标与 `campus3d.json.projection` 相同，附原地图来源。
- `gis/entrances.geojson`：同一批入口反算为 WGS84；原六个 GIS 文件不重写。

每栋楼只设一个 `source: inferred` 入口。追加修正后，先合并外轮廓上的共线墙段，再从朝向道路的外墙中点中选择距离步行图最近的候选，不把门放在转角或棱边。`facade` 记录墙段，`outward` 记录单位外法线，`placement: facade_midpoint`；门框与墙面对齐。沿法线出墙后经最近道路线段上的投影点连接到该边的原始端点，记录 `road_node_id` 与 `connector`；不向 A* 图添加节点/边。去程、返程都以同一扇门为起终点。入口不是实测校门或真实可进入许可。

没有步行边的调用方 GeoJSON 仍可建模，入口标 `connected: false`、无节点及连接线；不会编造道路。当前中科大 31 栋楼均有可连接的推断入口。OSM entrance 支持留待后续。

新文件写入 scenario.json 的 SHA-256，目录 index.json 同步记录新清单哈希；已有 `-text` 规则原样保存 JSON/GeoJSON。除清单/目录增加哈希外，原地图、地表、人物、订单、地点映射、道路图及六份 GIS 图层保持原始字节。

## 一份状态，两种显示

`frontend/src/mecoffe/indoorMotion.js` 的 `IndoorMotion` 是沙盘和 GIS 共用的展示控制器。按同一回放位置、事件序列、设置和固定 60 Hz 展示时钟，生成一致的人员状态与楼内名单；回退拖动重算同一状态。动画清场时间可继续推进已到游标之前的行程，但不会提前读取未来购买事件。

状态顺序：楼内等待 → 出家门 → 前往门店 → 进店 → 隐藏并在店内停留 → 出店持杯 → 回家 → 进家门 → 隐藏。进/出门各约 0.5 展示秒，沿门的法线穿过墙面约 2 展示米并缩小/恢复；进门完成后计入楼内。店内默认停留 6 展示秒。它们按回放倍速换算为墙钟时间。

配置入口为 `INDOOR_DEFAULTS` / 构造参数 `options`：`doorSeconds`、`shopSeconds`、`speedMps`、`headwaySeconds`、`secondsPerDay`、`hz`。这不是对现实购物时长或步速的估计。既有每店 2 人、总计 12 个展示行程上限继续保留；同路线错峰出发，不改变订单统计。

只有走路、进门、出门的人参加渲染和 LOD。楼内的人保留画像、历史、所在楼栋和名单，选择时定位/高亮楼栋，不强行显示人形。楼顶人数仅计真正处于楼内的状态；过门的人归室外，因此楼内人数加室外人数始终等于人物总数。没有轨迹的场景不创建人物。

楼顶人数为零时隐藏；远景隐藏/避让。楼体或屋顶仅作轻度提亮，保留类别颜色和 YuLan 建筑风格。GIS 可查询推断入口；两种页面的楼栋卡都能点击楼内名单进入人物资料。室外人物始终有清晰的 DOM 定位点，模型准备中或被楼体遮挡也不会丢失入口；离开当前视口时仍能从人物列表定位。页面“人物去向”显示室外数加楼内数，检查漏分配和无效位置。

本轮按用户指定把商家一号的展示映射改为学生食堂B区，商家二号保留教工食堂；只改地点映射源文件及其场景派生文件，不改人物、订单、关注关系或道路图。两店仍为示意地址。

`Campus3DScene` 无入口参数的旧构造调用保留兼容分支，便于旧几何/碰撞 API 测试；真实页面强制加载入口，走 `Campus3DIndoor`，不调用 standingSlots 排列常驻人物。旧二维 `/mecoffe` 不在本轮改动范围。

## 日期与性能

按日回放显示“第 N 天 · 日期”，天内显示回放百分比，不展示钟点；光照仍可切换，注明是展示效果。无 OASIS 数据的小时场景沿用小时步长，显示“第 N 小时 · 日期”，同样不把光照钟点当作行为时间。

实际已有购买走廊在地图加载阶段准备，播放中复用；不据此生成新购买。不为楼内人物发起新的 FBX 请求或绘制，已加载模型仍由原有缓存管理；静止人数标签不每帧反复排版。GIS 播放绘制上限为 90 Hz，实际频率受设备限制，暂停时只因交互/素材准备而绘制。性能原始数据与截图见 `logs/milestone9/`；内存数字为主线程 JS heap，不含 GPU、worker 或整进程 RSS。
